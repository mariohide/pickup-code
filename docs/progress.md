## 界面定稿（2026-10-22）

细节已写进规格和代码注释，这里只列结论，以及试过又放弃的做法。

- **卡片**：取件码用 6 个小灰点遮挡，按钮用 primaryContainer tonal 样式（既有主色语义与对比度，又避免长列表中多个卡片重复实心 primary 造成视觉压迫，2026-10-22 改），底部一行次要信息（左「尾号 · 快递公司」，右到件日期，outline 色），卡片内不加分隔线。同组卡片用 Expressive 分段形状：首尾 16dp 大圆角，中间小圆角，2dp 窄缝。
- **揭码**：码始终参与测量，圆点叠放在上面，揭码前后卡片高度不变，不写死高度。动画只是一个不回弹的短交叉淡化。
- **首次加载**：骨架屏（`PickupListSkeleton`），按真实布局排出汇总、两组组头和 3 + 2 张分段卡片，高度与内容一致；占位块明暗呼吸，不用扫光（2026-10-22 定）。
  - 放弃：居中的 Expressive LoadingIndicator。
- **汇总**：一行「4 件待取」，数字用大字，不做数字滚动动画。
  - 放弃：右侧的说明文字「查看取件码即标记已取」，它和组头的「查看全部取件码」叠在同一侧，顶部显得杂乱（2026-10-22 去掉，DataStore 随之移除）。
- **组头**：地点名 +「（N 件）」，不加地点图标；地点名用 titleMediumEmphasized 强化分组层级（2026-10-22 改）；「查看全部取件码」是标准眼睛图标按钮（无底色，低强调，带 IconButtonDefaults.shapes()）。按 MD3 对齐线：左边文字、右边图标各贴一条 16dp 对齐线，眼睛图标右缘与卡片右缘、顶栏齿轮同一条竖线，触控区伸进留白，同 M3 顶栏（2026-10-22 定）。
  - 放弃：20dp 地点图标（与眼睛不对称，且是装饰）；地点图标放大到 24dp（太大）；浅色圆底的眼睛按钮（中等强调，与卡片按钮同档，每组一个会抢眼）。
- **顶栏**：仿 Google 相册（2026-10-23 定），做成可复用的 `ui/component/ScrollAwayTopAppBar`（列表与整页滚动各有 `remember…State`）。顶栏不放进 Scaffold，自己叠在列表上；列表上内边距固定为状态栏 + 顶栏高度，顶栏按列表实际滚过的距离 1:1 平移（`graphicsLayer`），最多移出顶栏 + 状态栏高度。顶栏比「贴着内容时应在的位置」（由首项偏移推算）更靠下即为浮起：浮起时顶栏与状态栏遮罩同为不透明 surfaceContainer，否则顶栏为 surface、状态栏为 surface 到透明的渐变。
  - 顶栏底色自己用 `drawBehind` 画、TopAppBar 容器色设透明：TopAppBar 会对传入的容器色再做一次动画，与状态栏遮罩先后变色。
  - 放弃：M3 `enterAlwaysScrollBehavior` 配 Scaffold padding。收起时靠缩小内边距把列表「拽」上去而非滚动，松手还会自动吸附，手感怪。
  - 放弃：Gmail 式，顶栏只移自身高度、滑进半透明状态栏遮罩下面。顶栏会隐约透出来像悬停；顶栏随内容滚却变色，隐喻不对。
- **下拉刷新指示器**：始终待在内容区内，随下拉淡入、放大并跟手下移一小段，使用 ContainedLoadingIndicator。
  - 放弃：默认的从顶栏下沿滑出（像从地下钻出来）；iOS 式整个列表下移（不采用）。
- **配色约定**：页面背景用 `surface`，卡片容器统一用 `surfaceContainerLow`（2026-10-22 定）；已取区通过整体透明度弱化（alpha = 0.72f）降低对比度，不再反向调换容器色。
  - 系统选了「单色」风格时，`primaryContainer` 在浅色模式下是深灰（MD3 单色方案有意反转明暗），引导页核心设计卡片会变成深底白字。这是用户自己的系统选择，不做特殊处理（2026-10-23 定）。
- **形态族统一**：全局按钮与图标按钮（含顶栏、重试、确认对话框）均显式声明 `ButtonDefaults.shapes()` / `IconButtonDefaults.shapes()`，支持 Expressive 触控形变（2026-10-22 定）。
- **页面切换**：MD3 共享轴 Z（父子页面之间，2026-10-23 定）。参数取自 MDC-Android 的 MaterialSharedAxis：前进时离开的页面放大到 1.1、进入的页面从 0.8 放大，返回时反过来；离开的页面在进度前 35% 淡出，进入的页面在其后淡入（35% 按缓动后的进度算）；450ms，强调缓动。用户评价「更现代」。
  - 方向按返回栈深度自己判断：返回手势打断进行中的前进时，NavDisplay 会把返回当成前进，套用前进的转场。
  - 两页先后淡出淡入、几乎不重叠，不依赖上下层。NavDisplay 垫 `surface` 底色，交替时不露出窗口背景。
  - Navigation 3 的默认转场是 700ms 匀速交叉淡化，不是 MD3 规范。
  - Navigation 3 用 1.3.0-alpha03（2026-10-23 升）：1.2.0 下进入动画没播完就手势返回，收尾会 `snapTo` 直接跳到终点，末帧整页缩放一顿（Pixel 上快速返回 3 次全中）；1.3.0-alpha01 改用 DeferredAnimatedContent 修了这个交接问题，实测 9 次都没跳。出正式版后升到正式版。
  - 1.3 的副作用：`NavDisplay` 用自己算的层级重建 `ContentTransform`（我们设的层级被丢掉），返回时离开的页面留在上层，转场结束前它仍接住点击，返回后约 0.45 秒内点刚回到的页面无效。对策：`rememberPoppedEntryReleaseDecorator` 在页面被移出返回栈、淡到全透明（约 70ms）后撤掉内容，只留不处理触摸的占位；退出途中又被打开时立即恢复。实测返回后 0.15 秒起的点击都有效；预测性返回取消后页面照常可用（2026-10-23）。
  - 性能：Pixel 2 XL 上来回进出设置 20 次，掉帧约 3.3%，GPU 99 分位 10ms，与滑动方案相当。转场中间的帧都在 16.7ms 内；掉的是两头：首帧组合加测量新页面约 45ms（表现为点击后动画晚一点开始，不是中途卡顿），末帧销毁旧页面约 25ms。按配置文件预编译还是全部预编译，掉帧都一样。要消除得把新页面首帧压到 16ms 内（`Scaffold` 子组合、中文文本测量等），收益只是老机型上少等约 30ms，暂不做（2026-10-23）。
  - 放弃：整页滑动覆盖加 dim（上层整页滑入、下层左移三分之一叠 scrim，提交于 9bc8a18）。不属于 MD3；且要自己按位置画遮挡与 dim：NavDisplay 不管上下层，AnimatedContent 只在页面首次组合时取层级，返回手势打断后层级会错。
  - 放弃：原生 `veilOut`/`unveilIn` 做 dim（画在页面外层，层级错时会压暗上层页面）；MotionScheme 的弹簧（Expressive 空间弹簧会回弹，效果弹簧与空间弹簧不同步）。
- **图标**：以瓦楞纸盒为灵感，选「立体纸箱」（2026-10-22 定）。启动图标是自适应图标：米色背景、三档牛皮纸色的三分之四视角纸箱加封箱胶带，并有单色层供主题图标使用；通知图标与单色层是同一个剪影。设计稿在 Figma 原型文件的「图标」页（组件「启动图标前景/E」「单色图标/E」），资源按设计稿导出的路径写成。
  - 放弃：包裹 + 遮码点、快递柜、取件码票签（第一轮）；正面封箱、开箱（第二轮）。
- **首次引导底部按钮区**：内容从后面经过时，底色换成不透明的 `surfaceContainer`，同清单浮起的顶栏；状态栏与清单共用渐变遮罩 `StatusBarScrim`（2026-10-23 改）。
  - 放弃：85% 半透明 `surfaceContainer`。MD3 的容器都不透明，按钮上方那行说明压在透出的正文上也难读；与清单的顶栏隐约不一致。
  - 放弃：底部长渐隐加悬浮按钮（不是 MD3 风格）。
  - 备选：不透明底栏（MD3 标准）；按钮悬浮、说明改为点击时弹 Snackbar（要改 onboarding §1）。
- Figma 原型已弃用，界面以真机为准。

## 性能（2026-10-23）

- **基线配置文件**：`:baselineprofile` 模块录「首次引导 → 清单滚动 → 设置 → 使用说明与权限 → 逐层返回」，结果提交在 `app/src/release/generated/baselineProfiles/`，覆盖清单、卡片、设置、引导、顶栏组件与导航。Pixel 2 XL 冷启动中位数约 192ms → 161ms；页面切换的掉帧不变。
  - 生成时被测的是 `app.pickup.benchmark`：在 buildTypes 里设后缀会被插件按 release 覆盖，只能在变体上设 applicationId；测试模块自我插桩，目标包名经插桩参数 `targetAppId` 传入。
  - Pixel 2 XL 上的「黑阈」会杀掉测试进程，配置文件在 S24 上生成。
- **手动安装的预编译**：「启动一次再 `compile -m speed-profile`」在 Android 15 上编出来是 `verify`（不合并刚写入的配置），改用广播写入配置再 `compile -r bg-dexopt`，见 AGENTS.md。此前按旧方法测的数据都是未预编译状态。
