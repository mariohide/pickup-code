# 首次引导

首次打开应用时，先说明这个应用怎么用、为什么要这些权限，再请用户逐项开启。

> 2026-10-23 起草，下列决定已确认，尚未实现。原型见 Figma「首次引导」页（https://www.figma.com/design/o202auUlAwNL6V1wD8H2mQ?node-id=42-59 ）：A 首次进入、B 开启后回来（含受限设置提示）。

## 1. 何时出现

- 首次启动时，引导页代替取件清单作为首屏。点「开始使用」即算完成，之后启动直接进入取件清单。
- **只有短信权限必需**（2026-10-23 定）：没有它清单永远是空的。
  - 短信权限未开启时，「开始使用」不可点，按钮正上方一行说明「开启短信权限后，才能开始使用」，否则用户不知道为什么点不动；开启后说明消失，按钮可点。
  - 通知、通知使用权都可选，没开也能进入清单。之后通知使用权由清单页横幅继续提醒；发通知被拒不加横幅（message_source.md §5）。
- 设置页加一项「使用说明与权限」，打开同一页面随时回看；从这里进入时，底部按钮改为「完成」，始终可点，点了回到设置（2026-10-23 定）。
- 引导是否完成记在本机；清空已取数据不影响它，卸载重装会再出现一次。
- 已经在用的人升级后也看一次：引导要讲清「看码即记为已取」，老用户同样需要（2026-10-23 定）。

## 2. 页面结构

单页，内容超出一屏时整页滚动。不做多页轮播：一屏能说清，省去翻页。从上到下：

1. **开场**：应用名与一句话——「从取件短信里找出取件码，按地点整理好，到了驿站直接看。」
2. **核心设计**，只讲一条：标题「看码即记为已取」，下面一句「到了驿站再点「查看取件码」，这件会同时记为已取。」（pickup_list.md §4）。说明只用一种字号、一段话；不写「先别点开」之类的强提醒：反悔很容易（就地撤销、已取区改回待取），留给用户自己探索；误点后按钮自己会说明（2026-10-23 定）。
   只讲这一条，因为它是唯一需要用户改变习惯的设计；按地点分组等一看清单就明白，不在引导里讲（2026-10-23 定）。
3. **权限**，每项一行，样式同设置页的分段列表：名称与用途占满行宽，下面靠右是操作按钮（文字见 §3）；已开启时同一位置换成「已开启」文字，高度不变，开启前后这一行不跳。操作不与文字并排：按钮与「已开启」宽度不同，并排会让每行的文字宽度参差，长说明还会被挤成很多行。靠右则各行的操作排成一列，与取件清单卡片上的按钮同侧（2026-10-23 定）。
   - **短信**（读短信、收新短信）：找出取件短信，新短信一到就整理；只在手机上解析，应用不联网。没有它清单是空的，所以排在第一项。
   - **通知**（Android 13 起才需要申请），名称旁标「可选」：「新包裹到了提醒你，只显示地点和待取件数，不显示取件码。不开也能用，只是不会提醒。」
   - **通知使用权**，名称旁标「可选」，用途写明为什么需要、不开会怎样：「取件短信到达时，短信应用和本应用会各响一次。开启后撤掉短信应用的那条，只响一次。不开也能正常使用。」（2026-10-23 定）
4. 底部按钮「开始使用」，固定在屏幕底部；短信权限未开启时不可点，上方附一行说明（§1）。

页面遵守界面约定（AGENTS.md）：不加装饰插图；核心设计不配图标；权限行不加分隔线。

## 3. 开启权限

按钮文字按全应用的口径（AGENTS.md「界面约定」）：弹系统权限窗、不离开本应用的写「开启」；要跳到系统设置的写「去设置」，后面带外跳图标（`Icons.Rounded.ArrowOutward`，同受限设置提示里的链接）。「去开启」不用：「去」暗示跳转，而弹窗并不跳转。

- **短信**：按钮「开启」，点了弹出系统权限窗，一次申请读短信与收新短信。系统已不再弹窗（拒绝过两次）时，按钮改为「去设置」，跳到本应用的系统设置页。
- **通知**：按钮「开启」，点了弹出系统权限窗；系统已不再弹窗、或在系统设置里关了本应用的通知时，按钮改为「去设置」，跳到本应用的通知设置页。Android 13 以下没有权限窗：通知开着就显示「已开启」，在系统里关了就是「去设置」。
- **通知使用权**：没有系统权限窗，按钮始终是「去设置」，直接跳到系统设置里本应用的通知使用权开关。
- 从系统权限窗或系统设置回到引导页时，重新检查各项，状态随即更新。
- 短信权限若也被受限设置拦下（用户会卡在引导页），暂不处理，遇到具体机型再加同样的提示（2026-10-23 定）。
- **受限设置**：从浏览器、文件管理器等渠道安装的应用（如从 GitHub Release 下载的 APK），系统可能拦截通知使用权，开关是灰的、点了提示「受限设置」。应用无法得知是否被拦截，所以：从系统设置回来后通知使用权仍未开启，就在这一行的用途下面加一句说明——「开关是灰的？到应用信息页右上角菜单里选『允许受限设置』，再回来开启」，其中「应用信息」是链接：主色、下划线，后面紧跟一个同色的外跳图标（`Icons.Rounded.ArrowOutward`，用 `InlineTextContent` 嵌在文字里，与文字同高，不加下划线，也在可点范围内；Figma 原型里的「↗」只是字符模拟），点了打开本应用的应用信息页。只有下划线不够醒目，图标表明会离开本应用（2026-10-23 定）。
  - **整段提示都可点**（2026-10-23 定）：句中链接只有几个字大，Compose 的文字链接也不会自动扩大点击范围（M3 的 48dp 最小触控只覆盖按钮等组件；WCAG 2.5.8 对句中链接有豁免，但豁免不等于好点）。这段提示只有一个操作，所以整段作为一个可点区域，点哪里都打开应用信息页，按下时整段出涟漪；上下留内边距，使可点高度不小于 48dp。「应用信息」及其外跳图标仍保留链接样式，说明这里能点、去哪里。入口嵌在句子里，说明和操作不分家；右下角仍只有「去设置」（2026-10-23 定）。

## 4. 与现有规则的关系

- **启动时不再自动弹系统权限窗**（2026-10-23 定）：现在缺权限时每次启动都会连弹系统窗，没有任何说明（message_source.md §5）。有了引导，申请改在引导页里、由用户点按钮发起；完成引导后缺的权限只靠清单页横幅提醒；横幅按钮按全应用口径改为「去设置」加外跳图标，跳转行为不变。
- 清单页横幅、通知、扫描时机等其余规则不变。
