# 消息来源、解析与去重

把取件短信变成取件清单里的包裹（字段见 pickup_list.md §1）。

> 目前只有短信这一个来源。通知来源（淘宝、拼多多等 App 的推送）以后再补，届时沿用 §3 的解析与 §4 的去重。

## 1. 短信来源

- 读取收件箱里的短信，需要短信读取权限（§5）。
- **新短信**：监听新短信广播，短信一到就按 §2–§4 解析、去重、入库，并发取件码通知（§6）。应用没在运行时系统也会拉起进程送达（2026-10-22 定）。
  - 不动扫描位置，之后扫描收件箱读到同一条短信时靠 §4 去重；入库后顺带扫描一次收件箱，让扫描位置越过这条短信，免得它被标记已取、清空后又被扫描当作新包裹导入。
  - 广播里的到件时间取收到广播的时刻，与收件箱记的到达时间相差不到一秒。
  - 走 RCS、5G 消息的「短信」既不发广播也不进收件箱，收不到。
- **扫描时机**：进入取件清单、应用回到前台、下拉刷新、短信权限刚开启时（2026-10-22 定）。新短信广播之外，扫描兜底补上广播漏掉的短信，如权限刚开启前到的。
  回到前台也扫，是因为常见的场景是：人在驿站门口收到短信，切回应用就应该能看到。
- **扫描范围**：从上次扫描读到的最后一条短信之后开始，按短信到达手机的时间计。首次扫描回溯 7 天（2026-10-22 定）。
  - 不重扫旧短信。所以在设置里清空的已取包裹不会被重新导入，催取短信也不会把它们带回来。
  - 例外：解析规则更新后，按首次扫描重新回溯 7 天，让旧规则漏掉的包裹补进来（2026-10-22 定）。已有的包裹靠 §4 去重，不会重复；但 7 天内清空过的已取包裹会作为待取再出现一次。
- **一次扫描整体写入**：中途失败就什么都不写，扫描位置也不前进，下次从同一位置重扫。
- 扫描在后台进行，界面上的呈现见 pickup_list.md §8、§9。

## 2. 哪些短信算取件短信

满足以下任意一条的短信产出包裹，其余短信忽略：

1. 含取件码关键词（取件码、取货码、提货码、取件密码、取件号），后面跟着码；或者「凭」后面直接跟码，如「凭1-5-1596到阳光小区3号楼取尾号1234包裹」。
2. 含「身份码」，如「出示淘宝身份码取件」。
3. 含凭手机尾号取件一类的说明，如「凭手机尾号取件」「报尾号取货」。

**排除**取出、签收通知（含「已取出」「已签收」「已被取走」）：这类短信也可能带着取件码，但包裹已经取走了。

## 3. 字段解析

解析前先去掉开头或结尾的签名，如【菜鸟驿站】，避免签名被当成地点。快递公司和是否快递柜例外，签名也参与判断，如【丰巢】。

| 字段 | 规则 |
|---|---|
| 取件码 | 关键词后的 4–16 位字母、数字，可含「-」，可带括号或引号，如 `3-2-1234`、`80123456`、「凭"72778"到…」。一条短信里有多个码（以「、」「，」「/」分隔）时，每个码各算一件包裹，其余字段相同 |
| 取件方式 | 有码时：提到柜子（丰巢、快递柜、智能柜、自提柜、「N号柜」、格口），算快递柜码，否则算货架码。没有码时：有身份码算身份码，有尾号取件算其他 |
| 柜号、格口 | 「7号柜」取 `7`，「23格口」「23号格口」取 `23`；「1号柜A16」取柜号 `1`、格口 `A16`；没有就空 |
| 身份码说明 | 「出示X身份码」，X 取「身份码」前紧挨着的平台名（淘宝、拼多多、菜鸟、京东、抖音）；没有平台名就写「出示身份码」 |
| 其他方式的说明 | 固定为「凭手机尾号取件」 |
| 快递公司 | 正文里第一个出现的公司名，按下表归一化。驿站、快递柜品牌（菜鸟驿站、兔喜、妈妈驿站、多多驿站、丰巢）不算快递公司 |
| 到件时间 | 短信到达手机的时间 |
| 手机尾号 | 「尾号」后紧跟的 4 位数字 |
| 取件地点 | 见下 |

快递公司归一化：申通→申通快递，中通→中通快递，圆通→圆通速递，韵达→韵达快递，顺丰→顺丰速运，京东→京东快递，极兔→极兔速递，邮政→中国邮政，EMS→EMS，德邦→德邦快递，百世→百世快递，丹鸟→丹鸟。

**取件地点**：

- 取「已到」「已到达」「已放至」「已放入」「已存放至」「已投递至」「已送达」等词之后，到第一个标点、「请」「凭」「取件」之前的文字。
  上面这些词都没有时，取「到」「至」「前往」等词之后到「取」「领取」之前的文字，如「凭1-5-1596**到阳光小区3号楼取**尾号1234包裹」。
- **归一化**，让同一个地点的不同写法归到同一组：
  1. 去掉空白。
  2. 「菜鸟驿站（阳光小区3号楼店）」这样括号前只有品牌名的，取括号里的内容；其他情况去掉括号及括号里的内容。
  3. 反复去掉末尾的「的」、柜号格口（「7号柜」「23格口」「1号柜A16」）、驿站与快递柜后缀（菜鸟驿站、妈妈驿站、多多驿站、兔喜生活、驿站、代收点、服务站、快递超市、丰巢智能柜、丰巢柜、丰巢、快递柜、智能柜、自提柜）。
  4. 例：「阳光小区3号楼菜鸟驿站」→「阳光小区3号楼」，「华强北路12号丰巢柜7号柜23格口」→「华强北路12号」。
- 结果少于 2 个字或多于 20 个字时，视为识别不出，归入「未识别地点」。

## 4. 去重

同一件包裹常收到不止一条短信，如到件通知和次日的催取提醒。新解析出的包裹若与库里已有的或本批先解析出的是**同一件**，就丢弃新的，保留先到的那件（2026-10-22 定）：

- 保留先到的，因为清单按到件时间排序，先到的更早被退回。
- 不论已有的那件是待取还是已取，都不改动它：已取的包裹不会因为一条催取短信而变回待取。

**同一件**的判断：

- **有取件码**：取件码相同，到件时间相差不超过 14 天，且地点相同。任一方地点识别不出时，不比较地点。
- **没有取件码**：取件方式、取件说明、地点、快递公司都相同，且到件时间相差不超过 3 天。
  同一天、同一驿站的两件身份码包裹会因此合并成一张卡片。这可以接受：到了现场出示一次身份码，就能把两件都取走。

## 5. 权限

- 运行时权限有三项：读短信、收新短信、发通知（Android 13 起）。只在首次引导页由用户点按钮申请，启动时不再自动弹系统权限窗（onboarding.md §4，2026-10-23 改）；之后缺的权限只靠清单页横幅提醒。收新短信与读短信同组，读短信已授权时系统直接给。
- **只有短信权限的横幅常驻、不能关**；其他权限的提示都可以关，并且在关之前就写明之后去哪里重新开启，免得用户不敢关（2026-10-23 定）。
- 横幅同时只显示一条，按轻重：短信 > 发通知 > 通知使用权。发通知关着时不显示通知使用权横幅：本应用不发通知，就谈不上与短信应用重复提醒。
- 发通知（Android 13 起）被拒或在系统里关了本应用的通知时，清单页顶部显示横幅，中性色，可关（2026-10-23 定）。
  - 文字：「通知已关闭，新包裹到了不会提醒。关闭此提示后，可在「设置 › 使用说明与权限」里开启。」
  - 文字下方靠右：「不再提示」与开启按钮。系统还会弹权限窗时，按钮是「开启」，点了弹窗；系统已不再弹窗、或在系统里关了本应用的通知时，按钮是「去设置」（带外跳图标），跳到本应用的通知设置页。同首次引导（onboarding.md §3）。
  - 「不再提示」与重新出现的规则同下面的通知使用权横幅，两条各记各的。
- 通知使用权（§6）无法弹窗申请，只靠横幅：短信权限与发通知都已授权、通知使用权未开时，清单页顶部显示横幅，中性色。
  - 文字：「通知使用权已关闭，取件短信会重复提醒。关闭此提示后，可在「设置 › 使用说明与权限」里开启。」
  - 文字下方靠右两个文字按钮：「不再提示」与「去设置」（带外跳图标，见 AGENTS.md 按钮口径，直达系统设置里本应用的通知使用权开关）。按钮放文字下方而不与文字并排：横幅文字长，两个按钮与它并排会把文字挤成很多行。
  - 点「不再提示」：横幅消失，记在本机，之后不再出现。重新开启的入口是设置页「使用说明与权限」（settings.md §3、onboarding.md）。
  - 开启过通知使用权、之后又被关掉时，横幅重新出现：这是新情况，之前的「不再提示」不再算数。
  - 「开启过」以本应用检查权限时看到它开着为准：清单页每次检查到开着，就清掉对应的「不再提示」（2026-10-23 实现）。

以下是短信权限：

- 首次引导里由用户点「开启」申请；用户拒绝两次后系统不再弹窗，此后只能去系统设置开启（onboarding.md §3）。
- 未授权期间，清单页顶部常驻横幅「短信权限已关闭，新到的包裹不会记录。」，附「去设置」（带外跳图标），跳到本应用的系统设置页（pickup_list.md §9）。没有关闭按钮：短信关着应用就收不到新包裹，必须一直提醒。不说「可能漏记」：读短信与收新短信同属系统的「短信」权限组，关闭时一起收回，之后到的包裹一件都进不来。横幅用 error 色系（errorContainer 底、onErrorContainer 文字与按钮）：短信是唯一必需的权限，比可选的通知使用权横幅（中性色）提醒得更重（2026-10-23 改）。横幅随列表滚动，不加图标。
- 从系统设置回到应用时重新检查权限：已授权就隐藏横幅，并立即扫描一次。
- 未授权时下拉刷新：照常按 pickup_list.md §7 重新归类，不提示「扫描短信失败」，因为横幅已经说明了原因。

## 6. 新包裹通知

新短信广播识别出新包裹时发一条通知（2026-10-22 定，2026-10-23 改为未取概览简报）。每批新包裹（一条短信）一条，覆盖上一条：通知栏里只留最新的概览，不会挂着几条件数不同的旧通知（2026-10-23 定）。

- **内容**：
  - 标题：`新包裹已到达xxx`（`xxx` 为这批包裹的取件地点；地点未识别，或一批里不止一个地点时，直接显示 `新包裹已到达`）。
  - 正文：`剩x件未取包裹，在x个地点。`（统计当前系统全部待取包裹的件数与地点数，不含取件码，保护隐私并方便掌握待取概览）。未识别地点的包裹合起来也算一个地点。读不到全部待取包裹时只统计这一批，通知照发。
  - 通知时间是这批包裹的到件时间。
- 点击打开应用，与点桌面图标相同。进入取件清单时清掉全部新包裹通知，因为通知里的包裹清单上都有。
- 去重后不算新包裹的（如催取短信）不发通知。
- 通知渠道「新包裹」，默认重要性（有声音）。

**同一条取件短信只提醒一次**：短信应用也会为这条短信发通知，取件短信的号码是服务商的，经常变，没法在短信应用里按会话静音。所以用通知使用权撤掉短信应用的这条通知（2026-10-22 定）：

- 只看默认短信应用的通知，取通知里最新一条短信的正文，按 §2 判断：是取件短信就撤掉。
- 识别不出的短信、取出与签收通知不撤，照常由短信应用提醒。
- 本应用没有收新短信或发通知的权限时不撤，免得一条提醒都没有。
- 催取短信也会被撤掉，而本应用因去重不发通知，所以催取短信不再提醒。
- 撤掉时短信应用的提示音可能已经开始，系统会随通知一起停掉；本应用的通知照常响。
