# 取件清单

应用首页。列出从短信、通知里识别出的包裹：待取的按取件地点分组，到了地点一次看全；看过取件码的包裹记为已取。

> 本规格只管清单页的展示与交互。消息来源、内容解析、去重见 message_source.md，这里只引用它们产出的包裹字段。

## 1. 包裹字段

清单页用到的字段，由解析产出：

| 字段 | 说明 |
|---|---|
| 快递公司 | 如「申通快递」；识别不出时为空 |
| 到件时间 | 消息到达的时间 |
| 取件地点 | 归一化后的地点名，如「阳光小区3号楼」；识别不出时为空 |
| 手机尾号 | 收件手机号后 4 位；短信里没有时为空 |
| 取件方式 | 见下表 |
| 状态 | 待取 / 已取 |
| 取件时间 | 记为已取的时间，待取时为空 |

| 取件方式 | 卡片上显示的内容 |
|---|---|
| 货架码（驿站） | 取件码，如 `3-2-1234` |
| 快递柜码 | 取件码；识别出柜号、格口时一并显示，如「7号柜 · 23格口」 |
| 身份码 / 扫码 | 「出示淘宝身份码」「出示拼多多身份码」等，没有取件码 |
| 其他 | 原文中的取件说明，如「凭手机尾号取件」，没有取件码 |

## 2. 页面结构

顶栏标题「取件清单」。本页是应用首页，不设返回按钮；右侧放设置图标按钮，见 settings.md §1（2026-10-22 定）。顶栏不常驻：列表往下滚时收起，往上滚立即出现；内容滚到顶栏下方时，顶栏与状态栏为半透明底色（2026-10-22 定）。从上到下：

1. 汇总：「N 件待取」，N 用大字（2026-10-22 定）。N 是状态为待取的包裹数。
   不加说明文字（2026-10-22 定）：原先右侧的「查看取件码即标记已取」与组头的「查看全部取件码」叠在同一侧，顶部显得杂乱。点击后按钮变成「撤销已取」，已经说明了包裹记为已取。
2. 待取区：按取件地点分组（§3）。
3. 已取区：标题「M 件已取」（§6）。与汇总「N 件待取」同句式，表明是与待取区并列的另一个区，不要做成地点组头的样式，免得被当成又一个地点；比汇总小、用低对比色，上方留 64dp 分开两个区（组与组之间是 16dp），不加分隔线（2026-10-23 改）。

**首次加载**：读取清单期间显示骨架屏，不显示居中的加载指示器（2026-10-22 定）。骨架按真实布局排：汇总一行，两组地点（组头加 3 张、2 张卡片），位置、高度与卡片形状都与内容一致，加载完替换时列表不跳动。占位块缓慢明暗呼吸，不用扫光；读屏读「正在加载」。

## 3. 待取区：按地点分组

- **分组依据**是取件地点，地点相同的待取包裹归为一组。
- **地点识别不出的包裹**归入「未识别地点」组，这一组排在最后。
- **组的顺序**：按组内最近的到件时间，从新到旧（2026-10-22 改）。刚收到短信打开应用，新包裹就在最上面。
- **组内顺序**：按到件时间从新到旧（2026-10-22 改）。
- **组头**显示地点名与本组列出的卡片数，件数放在括号里，如「阳光小区3号楼（2 件）」（2026-10-22 定）；地点名使用强调字阶 `titleMediumEmphasized` 提升分组首要辨识度（2026-10-22 改）。不加地点图标：地点名已足够说明分组，文字直接贴左侧对齐线。本页内刚记为已取、还留在原位的卡片也算在内（§7）。
  组内待取件数 ≥ 2 时，组头右侧显示「查看全部取件码」图标按钮（无底色的标准眼睛图标按钮，每组一个所以用低强调；图标右缘贴右侧对齐线，与卡片右缘、顶栏齿轮在同一条竖线上；无障碍描述「查看全部取件码」，2026-10-22 定）（§5）；只有 1 件时不显示，用卡片自己的按钮即可。
- **信息主次**（2026-10-22 定）：取件地点 > 取件码 > 手机尾号、到件日期 > 快递公司。
  到了现场，用户先要找到地点，再报码；快递公司对取件几乎没有用处，只作补充。
- **卡片不再重复地点**，地点由组头承担。卡片只有：取件方式区（§4）在上，一行次要信息在卡片底部——左侧「尾号 · 快递公司」（如「尾号 1234 · 申通快递」），右侧到件日期（如「10月20日到件」）（2026-10-22 定）。
- **卡片不加状态标签**（2026-10-22 定）：待取区、已取区本身就表明了状态。唯一的例外是本页内刚记为已取、还留在原位的卡片，它靠按钮文字「撤销已取」表明状态（§4.1）。
  手机尾号或快递公司为空时，那一项连同分隔点一起省略。

## 4. 卡片的取件方式区

- **有取件码的**（货架码、快递柜码）：取件码用 6 个圆点遮住，右侧按钮「查看取件码」。
  圆点个数固定为 6，与取件码实际长度无关。
- **没有取件码的**（身份码、其他）：直接显示取件说明文字，右侧按钮「标记已取」。
- **待取按钮样式**（2026-10-22 改）：采用 `primaryContainer` tonal 样式（带主色调高对比度，同时避免多卡片重复纯实心 primary 产生视觉压迫），并显式声明 `ButtonDefaults.shapes()` 支持动态形变。

### 4.1 查看取件码 / 标记已取

点击后：

1. 卡片**原位**显示取件码（快递柜码连同柜号、格口）；没有取件码的卡片保持显示说明文字。
2. 包裹立即记为已取，记下取件时间。
3. 按钮换成「撤销已取」。文字同时说明了两件事：这件已经记为已取，以及可以撤回。
4. 汇总里的待取件数立即减少。所在组头的件数不变：组头数的是本组列出的卡片。

**为什么看码即记为已取**（2026-10-22 定）：取件没有任何回调，驿站和快递柜都不会在取件后发来通知，手动标记又不应该成为负担。到了驿站一定会看码，所以把看码当作取件的信号。用户只需要记住「没到驿站，先别点开」，这比「取完记得点已取」直观。误点了可以就地撤销，离开本页后也能在已取区改回待取，补救已经足够。通知中不显示取件码（message_source.md §6），仅在清单里查看取件码时记为已取。

卡片**不移动**：留在待取区原位，直到离开本页（§7）。到了驿站后用户可能要反复看取件码：报给店员、去货架找、在快递柜上输入。卡片一旦移走，就得再去已取区找。

### 4.2 撤销

点击「撤销已取」：包裹恢复为待取，取件时间清空，取件码重新遮住，按钮回到「查看取件码」 / 「标记已取」，汇总件数加回。
卡片同样不移动。

## 5. 查看全部取件码

点击组头的「查看全部取件码」，先弹出确认对话框（2026-10-22 定）：一次会把整组记为已取，误触的代价比单张卡片大。

- 标题「查看全部取件码？」，正文「本组 N 件待取包裹将显示取件码，并全部记为已取。之后可以逐件撤销。」
- 按钮「查看」「取消」。这个操作可以撤销，「查看」不用错误色。

确认后，组内**所有待取**包裹一次按 §4.1 处理，包括没有取件码的包裹（人到了这个地点，同样会一起取走）。

- 之后每张卡片可以单独「撤销已取」。
- 组头按钮是否显示，始终按 §3 的条件（组内待取件数 ≥ 2）实时判断：查看全部之后隐藏，撤销后待取件数回到 2 件及以上时重新显示。

## 6. 已取区

- 列出最近 30 天内记为已取的包裹，**不分组**，按取件时间从新到旧：取件时间是点「查看取件码」或「标记已取」、记为已取的那一刻，不是到件时间；「查看全部取件码」一次记下的几件取件时间相同。越晚取的越靠上，方便反悔：误点了或想改回待取时，要找的那件就在最上面（2026-10-23 明确）。
- 不按地点分组：已取区主要用来补救，人记得的是「刚才那件」，按时间找最快；再分组会出现一排与待取区相同的地点组头，分不清身在哪个区。地点改作卡片标题（见下）。
- 卡片样式与待取一致，整体降低对比度：容器与待取卡片统一为 `surfaceContainerLow`，通过整体透明度（`alpha = 0.72f`）降低对比度弱化呈现（2026-10-22 定）。这里不分组，所以**地点作为卡片标题**，次要信息行同 §3；取件码直接显示，不遮挡。
- 按钮「改回待取」：效果同 §4.2 的撤销，卡片同样不移动。

## 7. 卡片何时重新归类

**原则：状态变化时卡片不动；离开本页后再进入时，按最新状态重新分组、排序。**

- **离开本页**指：返回退出本页，或从本页进入其他页面后再返回。
- 应用切到后台、锁屏后回来**不算离开**，卡片保持原位。在快递柜前锁屏再点亮是常见操作。
- 应用在后台被系统回收后再打开，按最新状态展示。这种情况下不保留原位。
- **下拉刷新等同于重新进入本页**（2026-10-22 定）：按最新状态重新分组、排序，卡片上的失败提示一并清掉。这是用户主动要求的整理，卡片换位置不算意外；刷新之后的状态变化照旧不移动卡片。
- 停留在本页期间到达的新包裹，按 §3 插入对应的组，不影响已有卡片的位置。

## 8. 刷新与空状态

- 进入本页、应用回到前台时自动扫描一次短信，补上漏收的包裹（message_source.md §1）。扫描过程不显示加载态，有新包裹时直接出现在列表里。
- 下拉刷新：立即扫描一次短信，并按 §7 重新归类；刷新期间列表保持可见。
  采用 M3 风格（2026-10-22 定）：列表不随手指下移；Expressive 的加载指示器全程在内容区内，随下拉进度淡入、放大、跟手下移一小段，不从顶栏后面滑出。
  刷新态**至少保持 700 毫秒**（2026-10-22 定）：让用户看清刷新已触发，否则刷新和取消下拉看起来一样；重新归类在刷新态结束时才生效。扫描耗时更长时按实际时间。刷新进行中再次下拉不重复触发。
- 没有待取包裹时，待取区显示「没有待取的包裹」，汇总显示「0 件待取」。
- 没有已取包裹时，不显示已取区。

## 9. 失败态

| 场景 | 呈现 |
|---|---|
| 进入页面时列表读取失败 | 整页显示「加载失败」与「重试」 |
| 查看取件码时，记为已取失败 | **取件码照常显示**，看码是主目的。按钮不换成「撤销已取」，卡片内提示「未能标记已取」与「重试」 |
| 撤销 / 改回待取失败 | 卡片保持操作前的状态，卡片内提示「撤销失败」，可再次点击 |
| 查看全部时部分包裹记为已取失败 | 所有取件码照常显示，失败的那几张按上面的第二行处理 |
| 进入页面时的自动扫描失败 | 静默，下次进入再扫 |
| 下拉刷新扫描失败 | 底部提示「扫描短信失败」，列表保持不变，不重新归类 |
| 短信读取权限或通知使用权被关闭 | 页面顶部常驻横幅：「短信读取权限已关闭，新包裹可能漏记」或「通知使用权已关闭，取件短信会重复提醒」，附「去开启」跳到系统设置，同时只显示短信那条；权限恢复后横幅消失（message_source.md §5）。短信读取权限关闭时下拉刷新只重新归类，不提示扫描失败 |
